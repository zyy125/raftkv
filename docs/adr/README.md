## 什么该进 ADR

- 架构设计与模块边界；
- 组件 / 引擎 / 协议选型；
- 持久化格式、编码方案等难以回退的决策；
- 面试能展开讲清“为什么这样选、否决了什么”的关键决策。

## 什么不该进 ADR

- 接口字段、参数与错误语义——放在代码注释和 `docs/design/`；
- 模块路径、Go 版本、Makefile target——由 `go.mod` / `Makefile` 直接记录；
- 实施顺序、里程碑拆分——随计划调整，不进入 ADR。
